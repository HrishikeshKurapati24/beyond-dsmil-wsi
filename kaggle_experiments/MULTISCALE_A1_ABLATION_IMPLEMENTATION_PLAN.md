# A1-based CAMELYON16 multiscale ablation and final test plan

## Question and fixed comparison

Does the released multiscale feature pipeline improve on the released uniscale pipeline when both use A1, and does learning the two scale contributions improve on fixed 20× + 5× concatenation? This study supersedes the older proposal to use single-anchor baseline DSMIL in the separate multiscale branch. All three variants use **A1 with four anchors and alpha fixed at 0.25**. Do not retune alpha or select a variant from the official test results.

| Variant | Patch input to the same A1 classifier | Training required |
| --- | --- | --- |
| U: archived A1 uniscale | Released 512-dimensional uniscale vector | Reuse the already obtained, verified official-test predictions and OOF threshold; no retraining or repeated test inference |
| M-fixed: A1 fixed multiscale | Concatenate the released 512-dimensional 20× and 512-dimensional 5× vectors | 15 new fits |
| M-adaptive: A1 adaptive multiscale | Learn a per-patch, two-scale gate before feeding the resulting 1024-dimensional vector into the otherwise unchanged A1 classifier | 15 new fits |

The multiscale input is the **`cat`** branch of the audited dataset, not the separate `fuse` branch. In each released row, columns 0–511 are 20× and columns 512–1023 are the matching 5× representation. The prepared multiscale dataset is expected to contain 399 float32 bags of width 1024. Its preprocessing completion marker records the scale-column mapping. Verify the attached Kaggle prepared dataset and this marker before training; fail on missing slides, wrong dimensions, nonfinite values, altered fold assignments, or a different scale order. The two blocks are already paired within a row. Do not join multiscale rows to the uniscale patch rows by position: the two released sources need not contain identical patch sets.

## Model specification

Let `h_i∈R^512` and `l_i∈R^512` be the paired 20× and 5× vectors for multiscale patch `i`.

* **M-fixed:** `x_i=[h_i || l_i]∈R^1024`.
* **M-adaptive:** form `g_i=softmax(W_g[h_i || l_i]+b_g)=(g_i^(20),g_i^(5))∈R²`, then `x_i=[2g_i^(20) h_i || 2g_i^(5) l_i]∈R^1024`. Use one linear 1024→2 gate with no hidden layer or auxiliary gate penalty. Initialize `W_g=0` and `b_g=0`, so `g_i=(0.5,0.5)` and M-adaptive initially equals M-fixed exactly. Train the gate and A1 classifier end to end. The factors of two make the initial vector equal to the original concatenation, rather than half its magnitude. Record the gate weights, entropy, and scale-wise effective feature norms for every held-out slide; interpret a gate weight as a learned preference, not proof of biological scale importance.

For **all** variants, retain A1's one instance scorer, four selected anchors, top-32 candidate pool, and greedy rank score `0.75 r_score + 0.25 r_feature`. The first anchor is the highest-scoring patch. For later anchors, `r_feature` ranks the candidate's cosine dissimilarity from the nearest selected feature. The rank selector is discrete and uses the same A1 tie rules. Feed the variant's `x_i` both to this selector and to A1's unchanged 128-dimensional query network. For each anchor `a_k`, compute `e_ik=q(x_i)^T q(x_a_k)/sqrt(128)`, `a_ik=softmax_i(e_ik)`, and `z_k=sum_i a_ik x_i`. Average the four `z_k` vectors, apply the bag classifier, and predict with `sigmoid(bag_logit)`. Keep the instance-stream max logit and loss `0.5 BCEWithLogits(bag_logit,y)+0.5 BCEWithLogits(max_i c_i,y)`. There is no attention-similarity penalty, learned anchor fusion, spatial term, or scale-specific classifier.

M-fixed and M-adaptive use 1024-dimensional A1 input-facing layers initialized from scratch; 512-dimensional uniscale weights cannot be transferred. Initialize the shared A1 layers identically for a matched fold/seed pair before initializing the adaptive gate to zero. This gives equal starting predictions for M-fixed and M-adaptive on the same input. Count and report the additional gate parameters.

## Data, training, and validation contract

1. Attach only the **prepared multiscale** Kaggle dataset. The prior uniscale A1 test output from `results-15` is stored compactly in `obtained_results/a1_alpha025_official_test/` and embedded in the notebook as a checksummed bundle. It contains 1,935 per-checkpoint predictions, 129 ensemble predictions, the test summary, 270 OOF probabilities, and provenance metadata. No A1 weights or uniscale feature bags are needed in this notebook. Keep the large multiscale feature input mounted read-only and stream one slide bag at a time.
2. Verify the multiscale source has the expected 399 slide IDs, canonical labels, official train/test split, and five fold assignments: 270 official-training slides, 54 validation slides per fold, and 129 `test_*` slides. Compare its IDs, labels, and folds with the embedded A1 OOF and test prediction manifests. Keep `test_114=normal`. Record dataset version and hashes. Differences in patch counts and extraction between released uniscale and multiscale sources must be summarized before interpreting U versus M-fixed.
3. Verify every embedded A1 test-result file against its checksum, all 15 seed/fold predictions per test slide, ensemble means, the OOF-derived threshold, and reported test AUC. If provenance or predictions fail, stop rather than rerunning A1 test inference or silently substituting a different reference.
4. Train M-fixed and M-adaptive independently on folds 0–4 and seeds 42, 43, 44: **30 new fits**. Match the existing A1 protocol: maximum 50 epochs, patience 10, Adam learning rate `1e-4`, betas `(0.5,0.9)`, weight decay `1e-3`, cosine schedule to `5e-6`, orthogonal linear/conv initialization and zero biases, bag size one slide, and checkpoint by maximum validation ROC-AUC with validation-loss tie break. Use the same deterministic seed and slide-order rules. No alpha or gate-architecture search is part of this study.
5. During fitting and selection, open only official-training bags. Save each epoch's train/validation loss, accuracy, and ROC-AUC; the best checkpoint and epoch; one OOF probability per validation slide, seed, and fold; and anchor and gate diagnostics. Every variant must have 15 verified checkpoints and 810 seed-specific OOF rows (270 distinct slide IDs × three seeds). Report per-fold/seed values, their distribution, and the OOF ensemble, keeping mean fold AUC distinct from OOF ensemble AUC.
6. Compare U with M-fixed to assess the **released feature pipelines as a whole**. Because their patch sets and extraction can differ, this difference is not a pure controlled test of adding 5×. Compare M-fixed with M-adaptive as the primary controlled fusion ablation: same multiscale rows, architecture downstream of the gate, training splits, and loss. Use paired fold/seed validation differences and paired slide-level OOF probabilities. Report whether M-adaptive's gate departs from the initial 0.5/0.5 and whether that varies across folds, seeds, and slide labels.

## Final official-test evaluation

Run this stage **after all 30 new fits, OOF records, and model-integrity checks are complete**. Freeze the three variants, checkpoints, ensemble rule, metrics, and threshold rule before opening test bags. Do not use official-test labels or predictions to change alpha, the gate, epochs, checkpoint selection, or which results are reported.

For M-fixed and M-adaptive, obtain the bag-stream probability from every fold/seed checkpoint for each of the 129 test slides, then average all 15 probabilities. Each new variant produces 1,935 checkpoint predictions and one ensemble probability per slide. **Use the archived U probabilities and summary directly**; verify their recorded 15-checkpoint means without loading U checkpoints. Derive each new variant's classification threshold by the existing Youden-J procedure on its three-seed ensemble OOF probabilities. U retains its previously frozen OOF threshold. Report threshold-free ROC-AUC as primary test metric, PR-AUC, and accuracy, balanced accuracy, sensitivity, specificity, and confusion matrix at the frozen threshold, plus accuracy at probability 0.5. Never fit a threshold on test labels.

Save per-checkpoint and ensemble test prediction CSVs, the OOF-derived thresholds, a three-variant test comparison table, exact source and checkpoint hashes, and a completion JSON. Use paired slide-level confidence intervals for test AUC differences if feasible; do not treat the 15 correlated checkpoints as 15 independent test datasets. Report `test_114=normal` in the provenance. Earlier project experiments have already exposed this official test cohort, so the multiscale test comparison is **exploratory on the project's existing holdout**, even though this study reserves it from its own fitting and tuning. A new external cohort would be required for a genuinely fresh generalization claim.

### Run the two independent multiscale ablations on T4 ×2

[Kaggle's T4 ×2 option](https://www.kaggle.com/docs/notebooks) provides two T4 GPUs with 16 GB VRAM each, while the session has shared CPU cores and host RAM. The M-fixed and M-adaptive validation fits are independent, so run **one process per variant**, with each process executing its own 15 fold/seed fits sequentially. This trains the two variants concurrently without distributed training or splitting a single slide across GPUs. Select T4 ×2 in the Kaggle notebook settings, then check `torch.cuda.device_count()==2` in the actual saved-version runtime. If fewer than two devices are visible, run the same two stages sequentially with unchanged seeds and settings.

Launch the two fresh Python subprocesses from a notebook orchestration cell. Set `CUDA_VISIBLE_DEVICES=0` for the M-fixed child and `CUDA_VISIBLE_DEVICES=1` for the M-adaptive child **before either child imports PyTorch**; each child then uses its visible `cuda:0`. Pass explicit variant, prepared-input, output-root, and source-hash arguments. Write to separate `/kaggle/working/multiscale-a1/M-fixed/` and `/kaggle/working/multiscale-a1/M-adaptive/` directories, and send each child's stdout/stderr to its own log. The notebook must wait for both exit codes, display useful progress, and fail if either child fails or any of its 15 checkpoints/OOF sets is missing. Do not start the final-test stage until both validation outputs pass integrity checks. A failed child may be rerun from verified completed fold/seed outputs only; never mix unchecked partial runs into the comparison.

Both children read the **same mounted, read-only** prepared multiscale dataset. Memory-map bags and load only one slide at a time; do not duplicate the roughly 17 GB prepared array collection in `/kaggle/working` or preload it into RAM. Kaggle's CPU cores, RAM, input I/O, and notebook runtime are shared even though each T4 has its own VRAM. Limit each child to one or two CPU threads and avoid extra data-loader workers. Before the full run, profile a large-bag forward/backward pass in both children simultaneously, recording per-GPU peak VRAM, host RAM, I/O wait, and elapsed time. Use the parallel schedule only if each child fits in its own GPU memory and combined host usage is safe; otherwise use the sequential fallback. The pilot is for resource planning, not model selection. Record the chosen schedule and per-variant wall time in the run manifest.

Use **Save Version → Save & Run All** for the orchestrating notebook; its top-level cell must remain active until both subprocesses finish and their outputs are verified. A background child left running after the notebook exits cannot be relied on for a saved version. Verify the embedded A1 test results before launching either child. After they finish, perform test inference for the two new multiscale variants one at a time on either T4; reuse A1's saved predictions.

Before a full Kaggle run, check: (i) the two 512-column slices reconstruct every sampled 1024-column input exactly; (ii) a zero-initialized adaptive gate gives exactly the M-fixed input, forward logits, and A1 anchors under matched A1 weights; (iii) gradients reach the gate; (iv) train/validation slide IDs never cross folds and no test bag is opened in validation stages; (v) all 15 predictions per test slide are present and finite; and (vi) OOF-derived thresholds and final metrics reproduce from saved predictions. Perform a short runtime/memory pilot on large bags, then execute the fixed protocol without changing it based on the pilot's validation outcomes.
